Checking whether GGUF support is present…

Temperature 0 is greedy: it takes the most likely token every time, which is how a small model ends up saying “yes, again, again, again”. Top-k and top-p cut the tail off the distribution; the repetition penalty makes a token that has already been used need to be more likely than before to be chosen again. 1 turns it off.

A GGUF file describes itself, so no conversion and no config.json: the architecture, the hyperparameters and the tokenizer all come out of the file. Quantized weights stay in the file's own block format on the device — a 0.6B Qwen3 holds at about 373 MB where float32 would need 2,274 MB. The file is read by range and never uploaded.

A Hugging Face folder is read as it is: its own config.json, its safetensors and the tokenizer files it was trained with. It carries no pin for this lab, so you will be shown the SHA-256 of every file before anything runs. A pytorch_model.bin is a pickle and is never executed; repack it with tools/repack_safetensors.py first.

Choose each folder itself, not its parent. The model must pin the selected plugin's exact manifest hash and name the checkpoint family that plugin implements. A checkpoint from another project (GPT-Neo or TinyStories, for example) needs a plugin written for it, and is refused here rather than loaded.
