# ZIPP 0.0.42

An audit release. Three real applications were profiled against Node.js until no single runtime path stood out, and each finding was fixed at its cause: twelve performance fixes and five correctness fixes. Applications run 2% to 22% faster than under 0.0.41, and long-running DOM workloads a further 6% on top.

## Benchmark Highlights (`v0.0.42` vs. `v0.0.41`, Node.js)

All measurements below were captured on Windows x86-64 with byte-identical output against **Node.js v24.19.0**, comparing matched local **non-PGO fat-LTO** builds of `v0.0.41` (`ed5be457`) and `v0.0.42`. The published binaries are PGO builds, whose absolute times differ.

## New in 0.0.42

- **Garbage collection:**
  - An Array callback method (`map`, `filter`, `forEach`, `find`, `some`, `every`, `reduce`) no longer holds the collection lock while its callback runs. A long callback chain could previously defer every collection until it returned.
  - A minor collection roots only the property maps written since the last collection, instead of walking the own-property tables of every old array and function. In long runs of DOM code this walk was the hottest instruction in the process.
- **Calls:**
  - A built-in global function called in tail position in strict code (`return Boolean(x)`, `String(x)`, `Number(x)`, `parseInt(s)`, and the rest) keeps its guarded opcode, and `Boolean(x)` is computed inline: 29 ns to 8 ns.
  - A compiled function entered from the runtime (a getter, a method reached through `call`, a parent constructor) has its global-route validation recorded, so the native call path accepts it again. Under the Node layer such functions stayed on the slow path for the rest of the run.
  - Derived-class construction and `super(...)` enter the parent constructor directly.
  - A missed inlined-leaf guard falls back to the native call path instead of a runtime helper.
  - A user method named like a built-in (`get`, `has`, `push`, ...) takes the user-method fast paths.
- **Objects and properties:**
  - Imported modules, `eval`, `new Function` and embedder scripts build object literals in one step, as the main script does: a four-key literal in a module goes from 118 ns to 14 ns.
  - A getter defined on an ES5-style prototype (`Object.defineProperty(P.prototype, ...)`) is found by the receiver's shape and called natively.
  - An Array's method is read from its live prototype slot.
  - Prototype versions recorded at setup are the marked ones, which re-enables the absent-property memo and the array-iterator check (both inactive since 0.0.34).
- **Fixes:**
  - A compiled loop reads a short string through its own buffer.
  - A read through a null prototype no longer teaches a shape that an inherited key is absent.
  - A private field's entry is charged to a metered heap when it is added.
  - A class that extends a bound function constructs it in `super()`.
  - The JSX grammar is left out of builds without TypeScript.
- **Tooling:** `bench/apps` is in the repository: the linkedom, defuddle and webforai workloads with a harness that runs ZIPP and Node.js side by side.
