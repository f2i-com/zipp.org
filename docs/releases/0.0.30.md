# ZIPP 0.0.30

A release for large programs on the interpreter. A bundled application of
256 functions or more now compiles each function body when it is first
called, so the parts of a bundle a run never enters are never compiled.
Its syntax tree takes about half the memory and every instruction half the
bytes, and the interpreter's property, call and collection paths are faster
on the code bundlers emit. Bundled applications take 0.78x to 0.97x
0.0.29's time, and the interpreter runs the 78 benchmark programs in 0.92x.

- **A large program compiles a function's body at its first call.** A
  script of 256 functions or more, which `zipp js` runs in the interpreter,
  leaves every body that can wait to its function's first call. TypeScript's
  compiler bundle defers 10,082 bodies and a run compiles 2,219 of them;
  Babel's defers 5,278 and compiles 1,966. A deferred body is compiled in
  the context the main compile saved, with the variables it captures
  resolved then, so it behaves as an eager compile would.
  `ZIPP_LAZY=off` compiles every program whole.
- **Less memory for code.** An instruction is 16 bytes, not 32, and a heap
  slot 64 bytes, not 80. A statement in the syntax tree is 80 bytes (176),
  an expression 48 (56), and lists are allocated at their length.
  Identifiers are interned once per spelling. After the parse, Prettier's
  syntax tree is 19.3 MB instead of 34.9, TypeScript's 46.5 instead of
  100.6, Babel's 26.7 instead of about 55. TypeScript's peak working set
  falls from 318 to 225 MiB.
- **The interpreter runs bundled code faster.** Among the changes:
  - an own field read or written through many object layouts is answered
    from the receiver's shape and a (shape, key) memo, without the general
    property path;
  - `f.apply(this, arguments)`, `f.bind(o)`, `Array.prototype.values.call(a)`
    and a native applied to a list run without the general method call;
  - `arr.pop()`, a private method call, a `Map` or `Set` method read into a
    variable, `x == null`, `===` against `undefined`, `null` or a boolean,
    and a run of integer `switch` cases each take one dispatch or one table
    lookup;
  - an absent field read through a class instance or through many AST
    layouts is cached;
  - a Proxy handler's trap and a built-in prototype's own method are read
    where they lie.
- **Collections cost less on large heaps.** A minor collection roots only
  the prototypes and literals stored since the last one, a major runs after
  256 minors rather than 64, and the adaptive nursery stops at 64K
  allocations so it fits a 32 MB cache. The per-slot tables grow in a few
  large steps, so Preact server rendering takes 8,505 page faults instead
  of 10,253.
- **`String.prototype.normalize` follows Unicode 18.0.**

## Changes in behaviour

- **`String.prototype.normalize` follows Unicode 18.0** (17.0 in 0.0.29).
- **The sandbox loader (`zipp.mjs` 1.4.0) checks its options more
  strictly.**
  - It reads only an options object's own properties, so a polluted
    `Object.prototype` can neither grant a permission nor turn off Worker
    isolation.
  - `isolate` must be a boolean; quotas, size limits and
    `limits.instructions` must be integers.
  - Seeded storage items and file entries count against their quotas, and
    a sandbox whose seeds exceed them does not start.
  - A trusted storage `backend` owns its data and limits, so it cannot be
    combined with `initial` or `quota`, and its `prefix` must be a
    nonempty string. Sandboxes sharing a backend and prefix share its
    state; give each tenant its own prefix.
  - A network allowlist entry must be an http(s) URL without credentials.
    Only a bare origin (`https://api.example.com`) grants its whole origin;
    any other entry is a URL prefix, so `https://api.example.com/?scope=read`
    no longer allows `https://api.example.com/other`.
  - Under isolation, a host function's return value must survive the
    Worker's structured clone. One that does not answers its call with
    `{ ok: false, error: { code: "host" } }`.
- **A large script's function bodies wait for their first call** (above).
  A syntax error anywhere in the script, a regular expression literal's
  included, is still reported before it runs.
- **`zipp js`'s code cache reads and prunes only folders it made.** A
  folder under `ZIPP_CACHE_DIR` that the cache did not create is never read
  or deleted: a cache folder holds a marker, and pruning removes a folder
  only when every file in it is a cache entry, never through a symbolic
  link or junction.

## Fixes

- **A self-recursive function with more than 255 parameters passed the
  wrong arguments to itself with the JIT**: the call's argument count was
  carried in eight bits. Such a call no longer enters the tier that
  truncated it.
- **`f.apply(t, a)`, `Reflect.apply`, `Reflect.construct`, `f(...a)` and
  `[...a]` read an array element redefined as an accessor from its old
  value.** `Object.defineProperty(a, 1, { get })` left the old value in
  the array's dense store, and those paths copied the store. They now run
  the getter, as Node does, and follow a getter that grows or shrinks the
  array.
- **`pop()`, `shift()` and `splice()` on an array whose `length` is
  non-writable threw before touching it.** The specification removes or
  moves the elements first and then fails the write of `length`, as Node
  does; they now do the same. `push()`, `unshift()` and frozen arrays still
  throw at once.
- **A primitive's property read consulted `Object.prototype` past a
  prototype set to `null`**: after
  `Object.setPrototypeOf(String.prototype, null)`, `"x".hasOwnProperty`
  was still the method. It is `undefined`, as in Node.
- **`zipp sandbox` (and `zipp js --sandbox`) took an error reading the
  child's output for its end**, so a failed pipe could pass for a
  complete, shorter result. It now reports the error.
- **Re-arming a heap limit after a conviction did not always collect.** A
  host that re-armed its limit (`set_heap_limit`) after a conviction, then
  again once the script had dropped what filled the heap, got no
  collection from the second re-arm, so the next allocations could be
  convicted at once. A re-arm now collects a heap that is over its new
  ceiling, and a conviction that leaves the heap past half the ceiling has
  the next re-arm collect too.
- **The browser engine's accelerator bridge had no reply limit.** A reply
  from `setAccelBridge`'s `compile` is now held to the 32 MiB the other
  synchronous host bridges allow, counted in UTF-8 bytes.

## Performance

Measured on 27 October 2026, native Windows x86-64 (Ryzen 9 9950X3D):

- the published 0.0.29 Windows binary;
- a plain release build of this release's code, as the published Windows
  binary is;
- Bellard's QuickJS 2026-06-04.

Every ZIPP binary runs with address-space randomization turned off, so
image placement does not move the numbers. Each run is pinned to one core
of the processor's die with the 96 MB L3 cache unless stated otherwise.
The figures are medians of interleaved runs.

**Bundled applications.** Each library is bundled into one script that runs
a fixed workload. Each figure is the median of 7 runs of `zipp js app.js`
in its default mode, and the time includes compiling the bundle. The 0.0.29
and 0.0.30 columns have the code cache off, as on a first run. The warm
column has the cache filled.

| Program | 0.0.29 | 0.0.30 | 0.0.30, cache warm | Bellard's QuickJS |
| --- | --- | --- | --- | --- |
| Babel: `@babel/standalone` transforms about 20 KB of modern JSX twice | 4.44 s | 3.45 s | 3.33 s | 3.63 s |
| TypeScript: `transpileModule` on about 40 KB of classes, generics and enums | 1.13 s | 0.91 s | 0.72 s | 1.04 s |
| Prettier: formats JavaScript, TypeScript and Markdown | 0.54 s | 0.44 s | 0.37 s | 0.44 s |
| marked, lodash, acorn, terser, three.js, immer, RxJS and date-fns | 0.81 s | 0.69 s | 0.64 s | 1.91 s |
| Vue server rendering | 95 ms | 81 ms | 72 ms | 85 ms |
| Preact server rendering | 76 ms | 74 ms | 71 ms | 71 ms |
| React server rendering | 75 ms | 69 ms | 64 ms | fails (no `TextEncoder`) |

On the die with the 32 MB L3 cache, 0.0.30 takes 0.78x (Babel) to 0.96x
(Preact) 0.0.29's time. There it takes 1.04x QuickJS's time on Babel and
Prettier, 1.02x and 1.03x on Vue and Preact, and 0.92x on TypeScript. A
profile-guided build of the same engine (`tools/pgo.sh`, which the
release does not ship) takes 0.82x to 0.94x QuickJS's time on Babel,
TypeScript, Prettier, Vue and Preact on the larger-cache die and 0.87x to
0.97x on the other.

Peak working set and page faults, cache off (mean of 3 runs):

| Program | 0.0.29 | 0.0.30 | Bellard's QuickJS |
| --- | --- | --- | --- |
| TypeScript | 318 MiB, 83,019 faults | 225 MiB, 57,845 | 114 MiB, 29,986 |
| Babel | 240 MiB, 65,060 | 245 MiB, 64,584 | 96 MiB, 25,431 |
| The eight libraries | 222 MiB, 57,047 | 210 MiB, 53,904 | 32 MiB, 9,432 |
| Prettier | 159 MiB, 40,881 | 126 MiB, 32,433 | 38 MiB, 11,163 |
| Vue server rendering | 51 MiB, 13,122 | 37 MiB, 9,654 | 20 MiB, 5,248 |
| Preact server rendering | 39 MiB, 10,253 | 32 MiB, 8,505 | 15 MiB, 3,784 |

Babel holds slightly more because a major collection now runs after 256
minors rather than 64, which leaves garbage longer in exchange for fewer
traces of its large old heap.

**The 78 benchmark programs** (median of 3 runs each; every output
identical):

- **Interpreted** (`ZIPP_NOJIT=1`, which leaves the regex JIT on, as in
  0.0.29's notes): 0.923x 0.0.29's time, faster on 74 of 78 and level on
  the rest. The largest gains are a burst of promise reactions (0.79x),
  `arguments.length` (0.80x), `try`/`catch` (0.81x), property reads and
  writes, the eight-way `switch` loop and zero-argument calls (0.82x
  each).
- **With the JIT**: 0.978x 0.0.29's time, faster on 59. Slower, each
  confirmed over 9 runs: a zero-argument call loop (1.08x), a survival
  workload (1.05x), sort variants and `new` objects (1.04x each), object
  literals (1.03x) and closure calls (1.02x).
- **Against Bellard's QuickJS** in the same runs, in that lane: the
  interpreter takes 0.825x QuickJS's time and is faster on 52 of the 78
  programs. 0.0.29 took 0.894x and was faster on 42. The largest gaps left
  are constructing objects and class instances (1.7x), `arguments.length`
  (1.6x), closure variable writes (1.4x), accessors and Proxy, and
  inherited reads (1.3x each).

The figures in the README and
[docs/PERFORMANCE.md](https://github.com/f2i-com/zipp.org/blob/main/docs/PERFORMANCE.md)
still describe the profile-guided 0.0.28 capture of 21 and 22 October
2026.

## Publishing

As for earlier releases, the engines the site serves are refreshed AFTER this
release exists, in one commit that:

1. sets `zippEngineRelease` in `landing/package.json` to `0.0.30`;
2. refreshes `landing/public/playground-runtime` and `landing/public/wasm` from
   `zipp-0.0.30-javascript-python.wasm` and `zipp-0.0.30-javascript.wasm`
   (`node crates/zipp-wasm/embed-kit/package.mjs extract`, then
   `sync-playground.mjs --refresh-engine`), SHA256SUMS-verified;
3. syncs the sandbox playground (`node landing/scripts/sync-sandbox.mjs` with
   the release's files, which brings the site's `zipp.mjs` to loader 1.4.0)
   and rewrites the site's Brotli copies (`npm run compress:engines`);
4. updates the version, size and SHA-256 that `landing/src/App.tsx` and
   `landing/README.md` state about the bundled engine.
