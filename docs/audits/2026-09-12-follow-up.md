# Zipp follow-up correctness and safety audit — 12 September 2026

This follow-up audits the working tree based on `8d20a17b` after the first
12 September correctness pass. It concentrates on re-entrant ECMAScript
operations, collector-visible temporary values, weak references, bytecode and
JIT metadata boundaries, and the browser host adapter. It does not change the
published performance claims or rebuild the checked-in WebAssembly release.

## Findings fixed

### ArrayBuffer, SharedArrayBuffer, TypedArray and DataView

- `ArrayBuffer.prototype.slice` now keeps the entry length through observable
  argument and species construction, checks the returned buffer's shared brand,
  rejects a detached source at the specified point, and copies only the source
  bytes still live after a re-entrant shrink.
- `SharedArrayBuffer.prototype.grow` uses a compare-and-swap retry so a
  re-entrant or concurrent larger growth cannot be overwritten by an older,
  smaller request.
- `TypedArray.prototype.set` re-reads the target length after offset coercion,
  snapshots overlapping sources, and preserves raw bits for same-kind copies.
  `copyWithin` likewise uses byte-preserving memmove semantics and returns before
  detached-buffer revalidation when the original copy count is zero.
- Numeric TypedArray and DataView arguments now use strict `ToNumber`, including
  the case where an object's primitive hook returns a BigInt.

### Numeric coercion

The runtime had one broadly reused conversion which intentionally accepts
BigInt for `Number`, relational comparison and `Intl.NumberFormat`, but several
algorithms that require strict `ToNumber` also used it. Those sites now reject
BigInt primitives, wrappers, and object-produced BigInts after running the
observable primitive-conversion protocol. The audit covered array-like lengths,
array and string indices, Date operations, RegExp limits, Math, DataView,
TypedArray, Atomics, JSON, Temporal and the relevant Intl services.

Date objects and boxed primitives no longer bypass an inherited or overridden
`@@toPrimitive`/`valueOf` hook in `Number`, `ToNumeric`, or NumberFormat paths.

### Promise combinators and iterator closing

Promise combinators now settle failures through the constructor-provided reject
capability. Iterator acquisition, resolve lookup, resolve calls and `then`
failures therefore preserve subclass behavior. When an abrupt completion is
already being processed, a throwing iterator `return` no longer replaces that
original reason.

### Temporary GC roots and collection iteration

- Iterator helpers root cached `next` functions, selected values, accumulated
  reducer state, concatenated pairs and the active iterator across callbacks,
  allocation and `IteratorClose`.
- Collection constructors root the adder, entries, keys and values while user
  accessors run. Decorator application roots intermediate class/member state.
- `Map.clear()` and `Set.clear()` leave iterator-visible tombstones in place, so
  an active iterator or `forEach` sees entries appended after the clear. Their
  hash index resets to an empty maintained index, and its live count now backs
  `size`/`LenOf`; repeated clear/add workloads no longer rebuild or rescan the
  full tombstone history for ordinary lookups.

### Weak references and finalization

WeakMap and WeakSet keys, WeakRef targets and FinalizationRegistry targets are
now registered as weak containers rather than accidentally becoming ordinary
strong graph edges. Major collection performs ephemeron closure; nursery
collection preserves values reached through live young/old keys without turning
dead keys into roots. WeakRef kept objects last through the current job and are
cleared at the job boundary. FinalizationRegistry cells keep held values and
tokens with their specified strengths, clear dead targets, queue cleanup once,
and preserve unregister behavior.

### Compiler and JIT bounds

Register windows, argument spans, array-literal lengths, computed class-field
indices, decorator argument blocks and tagged-template metadata now use checked
allocation/conversion at their `u16` bytecode boundary. Oversized source returns
a compile error rather than wrapping into neighboring registers. Both native
JIT planners also validate control targets, register operands and multi-register
windows before indexing metadata; malformed plans decline to the interpreter.

### Browser host adapter

The reference SDK is now version 1.1.1. Both sides render arbitrary thrown
values defensively, including hostile `message`/`name` accessors, failed string
conversion, null-prototype objects and revoked proxies. Error reporting can no
longer strand a request or its deadline, and the real Worker adapter is covered
by a Node worker-thread contract test.

The landing toolchain was refreshed to `@cloudflare/vite-plugin` 1.54.8 and
Wrangler 4.131.1. The site typecheck, tests and production build remain clean.

## Remaining known limits

The three existing core Test262 expectations remain narrowly classified:

- `annexB/language/function-code/block-decl-func-skip-arguments.js` conflicts
  with current specification wording and is tracked upstream in Test262 issue
  #5113.
- Both modes of `staging/sm/String/internalUsage.js` assume German date data;
  Zipp currently bundles English CLDR data.

Map/Set tombstones cannot be compacted while their specification-visible cursor
positions may still be observed. Clear-heavy collections can therefore retain
backing capacity until collection; that memory is included in the VM heap
account and bounded by the configured ceiling. Lookup and `size` no longer scan
that history, and iterator scans remain charged to the native-work budget.

Runtime-compiled function/class reclamation remains the ownership redesign
recorded by the first audit. Nothing in this follow-up widens that lifetime.

Automatic GitHub workflow triggers remain paused. The eight new regression
binaries are included in both retained manual workflows so they run when CI or
the security matrix is invoked explicitly.
